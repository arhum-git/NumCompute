A modular streaming classification framework built with **plain Python, NumPy and matplotlib**. It extends the submitted NumCompute (Assignment 2.1) by adding incremental preprocessing and metrics, a depth-limited decision tree, **buffered periodic retraining**, a stream trainer, and reusable plots. The existing `numcompute/` package and its tests have not been modified. The earlier README is kept as `README_assignment2_1_original.md`.

## Basic usage

```python
from numcompute_stream import (
    DecisionTreeClassifier, StandardScaler, SimpleImputer,
    Pipeline, StreamTrainer, iter_csv_chunks,
)

model = Pipeline([
    ("impute", SimpleImputer(strategy="mean")),
    ("scale", StandardScaler()),
    ("tree", DecisionTreeClassifier(max_depth=5, buffer_size=80)),
])
trainer = StreamTrainer(model, window_size=100)

for X, y in iter_csv_chunks(
    "demo/dataset/test_student_performance_data.csv", chunk_size=40,
    feature_columns=["Age", "StudyTimeWeekly", "Absences", "GPA"],
    target_column="GradeClass", skip_missing_targets=True,
):
    print(trainer.process_chunk(X, y))

print(trainer.metrics.result()["confusion_matrix"])
```

## Model and pipeline streaming behaviour

- `tree.fit(X, y)` immediately fits one tree from scratch and clears pending chunks.
- `tree.partial_fit(X_chunk, y_chunk)` appends samples to an internal buffer. Once the buffer has **at least** `buffer_size` samples, the tree retrains **once on all buffered samples** and clears the buffer (including overshoot). It does **not** incrementally adjust existing splits. Prediction between retrains uses the most recently fitted tree. Before the first fit, `predict()` raises `RuntimeError`.
- `Pipeline.partial_fit(X, y)` updates incremental transforms for each new chunk and holds **raw input** until its final tree's threshold is reached. It then transforms the complete raw buffer using the **current** preprocessing parameters and calls the buffered tree. When one-hot width expands, it performs a fresh tree fit at the threshold. Predicting between retrains uses a deep-copied snapshot of transformations paired with the latest tree; this prevents feature-width/scale drift errors.
- `StreamTrainer.process_chunk(X, y)` scores with the existing model **before fitting**. Initial chunks cannot be evaluated and are logged with `NaN` accuracy. Logs include chunk accuracy, cumulative accuracy/F1/AUC, retraining flags, fitting time, buffered NumPy bytes, and traced peak Python memory bytes. The memory quantities are **not** process RSS.

### Numeric and categorical conventions

- The bundled demo CSV has one missing target label. The custom reader supports explicit `skip_missing_targets=True` to discard it; the default is to reject missing labels.
- All numeric model/scaler arrays are 2D `(n_samples, n_features)`; targets and outputs are 1D `(n_samples,)`. Missing numeric features can be NaN, but infinite values and missing target labels are rejected.
- Tree split thresholds are selected by Gini or entropy with deterministic lower-index class ties; missing values are routed to the child giving lower weighted impurity (left on ties). `max_features` can be `None`, integer, fraction, `'sqrt'`, or `'log2'`.
- The online standard scaler and moment tracker ignore NaNs when updating statistics and guard zero-variance/all-missing columns. Imputers can be mean, median, or constant. The encoder discovers categories incrementally; new features are **appended** to avoid renumbering existing columns.
- Streaming accuracy/precision/recall/F1/confusion use vectorised counts. Exact binary AUC needs **probability or decision scores**, which the tree supplies through `predict_proba()`. `NaN` AUC means a score series or a class is unavailable. Per-sample rolling windows are supported.
- **Memory trade-off:** exact median, quantiles and scored AUC cannot generally be maintained with constant RAM over an unlimited stream; they retain observations/scores. For stats, choose `history_size` for bounded *rolling* quantiles. Fixed-range histogram counts are bounded, using `histogram_range`.

## Tests and benchmarks

Run all original and new tests together using `python -m pytest -q`. All old modules are preserved so the course's original suite continues to run. New tests check buffer threshold and overshoot, predictions before and between retrains, mixed streaming chunk sizes, snapshot correctness, NaN splitting, numerical moments, AUC ties, CSV errors, plots, full pipeline execution, and internal `TypeError` propagation.

`benchmark/stream_benchmark.py` uses a seeded synthetic stream with concept drift. It compares a loop-based confusion matrix against NumPy `bincount`, checking both return identical results; warm-up plus best-of-7 measurements are used. It also compares different buffer sizes by **prequential accuracy**, evaluated sample count, number of retrains, and total fitting seconds. A larger buffer delays the first prediction, so evaluated sample counts differ; those counts are reported rather than treating the comparison as identical test sets.
